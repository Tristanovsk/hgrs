Configuration
=============

Quick start
-----------

hGRS needs the folder of the look-up tables (LUTs, see :doc:`installation`). Write it in your user
configuration file and check it with:

.. code-block:: bash

   hgrs_config --init /path/to/lut   # creates ~/.config/hgrs/config.yml
   hgrs_config                       # prints the configuration in use and checks the LUTs

Nothing else is needed: all the other settings have default values. The configuration is read at run
time, so it can be changed without reinstalling the package.

``hgrs_config`` ends with the status of each LUT and returns the exit code 1 if one is missing::

   LUT toa           ok      /path/to/lut/toa_lut_opac_wind_up_v3.nc
   LUT transmittance ok      /path/to/lut/transmittance_lut_opac_wind_v3.nc
   LUT abs_gas       ok      .../hgrs/data/lut/lut_abs_opt_thickness_normalized.nc

The processing also checks the LUTs before reading the image, and stops with a message giving the
missing files.

Where the settings come from
----------------------------

The settings are merged from, in increasing order of priority:

.. list-table::
   :header-rows: 1
   :widths: 35 65

   * - Source
     - Content
   * - Packaged defaults, ``hgrs/config/default_config.yml``
     - All the settings (see `Settings`_ below). Do not edit this file: it is replaced when the package
       is reinstalled.
   * - User configuration file, ``~/.config/hgrs/config.yml``
     - Only the keys to change, with their parent keys. Its location is
       ``$XDG_CONFIG_HOME/hgrs/config.yml`` if ``XDG_CONFIG_HOME`` is set, or the file given by the
       ``HGRS_CONFIG`` environment variable.
   * - ``HGRS_DATA_ROOT`` environment variable
     - Folder of the LUTs (``path: data_root``).

``hgrs_config --init`` writes the user file with the folder of the LUTs and, commented, a copy of all
the default settings: to change one, uncomment it with its parent keys. It does not overwrite an
existing file, unless ``--force`` is given.

Environment variables
~~~~~~~~~~~~~~~~~~~~~

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - Variable
     - Effect
   * - ``HGRS_CONFIG``
     - Path of the user configuration file to use instead of ``~/.config/hgrs/config.yml``
       (error if the file does not exist).
   * - ``HGRS_DATA_ROOT``
     - Folder of the LUTs; takes priority over ``data_root`` in any file.
   * - ``HGRS_PREVIOUS_BEHAVIOR``
     - ``1``, ``true``, ``yes`` or ``on``: former parameters and algorithms (see
       `Former behavior`_); any other value: current ones. Takes priority over ``previous_behavior``
       in the user file.

Examples
--------

Change the smoothing of the aerosol optical thickness (e.g. no smoothing) in
``~/.config/hgrs/config.yml``:

.. code-block:: yaml

   path:
     data_root: '/path/to/lut'

   atmospheric_correction:
     aerosol:
       smoothing_method: none

Use a larger retrieval grid (mega-pixels of 30 x 30 pixels) and a stricter water mask:

.. code-block:: yaml

   atmospheric_correction:
     product:
       x_coarsen: 30
       y_coarsen: 30
       ndwi_threshold: 0.05

Run a batch with its own settings, without changing your user file: write the settings of the batch
in a file and give it with ``HGRS_CONFIG``:

.. code-block:: bash

   export HGRS_CONFIG=/path/to/batch_config.yml
   hgrs_config                       # check
   parallel -j 4 < hgrs_commands.txt

In Python, the configuration in use is given by :py:func:`hgrs.config.get_app_config`:

.. code-block:: python

   from hgrs.config import get_app_config

   config = get_app_config()
   config.data_root
   config.atmospheric_correction.aerosol.smoothing_method

Former behavior
---------------

``previous_behavior: true`` in the user file (or ``HGRS_PREVIOUS_BEHAVIOR=1``) selects the former
parameters, ``hgrs/config/old_config.yml`` in place of ``default_config.yml``, and the former algorithms
(spectral response functions, gap filling of the water vapor and aerosol retrievals, transmittance
for the scene-mean AOT), to reproduce the products of previous versions. The user file is still
applied on top of the former parameters.

The switch is read when ``hgrs`` is imported; in a script or notebook, it can also be changed
afterwards:

.. code-block:: python

   from hgrs.config import behavior
   behavior.PREVIOUS_BEHAVIOR = True

Troubleshooting
---------------

``LUT file(s) not found``
   The folder of the LUTs is not set or is wrong: run ``hgrs_config`` to see the paths in use, then
   ``hgrs_config --init /path/to/lut --force`` (or edit ``data_root`` in the user file). An
   ``HGRS_DATA_ROOT`` variable set in your shell takes priority over the file.

``Unknown ... setting(s)``
   A key of the ``atmospheric_correction`` section of the user file is misspelled or misplaced:
   compare with the `Settings`_ above (each key must be under its section: ``product``,
   ``water_vapor`` or ``aerosol``).

``HGRS_CONFIG points to a missing file``
   Unset ``HGRS_CONFIG`` or correct the path.

The settings seem ignored
   Check with ``hgrs_config`` which user file is read (``found`` / ``not found``) and the merged
   configuration; the YAML indentation decides the section of each key.

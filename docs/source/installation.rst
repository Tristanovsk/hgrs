Installation
============

Look-up tables
--------------

The radiative transfer look-up tables (LUT) are not part of the package. Download them from
`this folder <https://drive.google.com/drive/folders/1r3unjh8UYTvO87nbppqivVq_cwbVxhLk?usp=sharing>`__
and save them in a directory of your choice (``your_LUT_PATH`` below).

Python environment
------------------

GDAL and xESMF (used for the geoprojection of PRISMA images) are easier to install with conda. From
the root of the repository:

.. code-block:: bash

   conda env create -f environment.yml
   conda activate hgrs

or, in an existing environment:

.. code-block:: bash

   conda install -c conda-forge gdal xesmf

Configuration
-------------

The default settings are in ``hgrs/config.yml``, inside the package. Do not edit this file: write
the settings you want to change in your user configuration file, ``~/.config/hgrs/config.yml``
(or ``$XDG_CONFIG_HOME/hgrs/config.yml``). Only the keys that differ from the defaults are needed,
typically the path of the LUTs:

.. code-block:: yaml

   path:
     data_root: 'your_LUT_PATH'

The user configuration is read at run time, so it can be changed without reinstalling the package.
Two environment variables are also available:

- ``HGRS_CONFIG``: path of a configuration file to use instead of ``~/.config/hgrs/config.yml``,
- ``HGRS_DATA_ROOT``: path of the LUTs, which takes priority over ``data_root`` in any file.

Print the configuration in use with:

.. code-block:: bash

   hgrs_config

Install the package
-------------------

From the root of the repository:

.. code-block:: bash

   pip install .

Then check the command-line tools:

.. code-block:: bash

   hgrs_enmap -v
   hgrs_prisma -v

For the visualization tools of the notebooks:

.. code-block:: bash

   conda install -c conda-forge jupyterlab holoviews hvplot panel datashader bokeh cartopy

Build this documentation
------------------------

.. code-block:: bash

   pip install ".[docs]"
   sphinx-build -b html docs/source docs/build/html

The example notebooks are not executed: they are rendered with the outputs saved in them.
